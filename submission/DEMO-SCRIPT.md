# Demo recording plan

## Prepared local recording

The local product recording must be labelled **Recorded locally — actual model inference — Vultr deployment pending — ASL unverified**. It demonstrates the actual model call, Avatar playback, pause/replay and the architecture. No fake cloud screen, synthetic usage metric or claim of accurate translation is permitted.

Suggested narration:

“Sign Companion explores a signed view beside English YouTube videos. This recording shows the local prototype; cloud deployment is still pending. I enter a sentence and explicitly consent to send it to the model. The backend returns actual RoboSTAR motion, which plays in the browser Avatar. The source sentence and measured request time stay visible. Pause and replay do not generate again. The YouTube extension adds caption lookahead and follows the video clock. The current model still has serious handshape and pose errors, so this is not a verified ASL interpreter. The next validation step is to resolve the motion conventions and work with fluent ASL users.”

## Cloud segment required for the requested competition deliverable

After an actual Vultr deployment works, record a separate segment showing:

1. The Vultr instance running, with passwords, tokens, account email and SSH credentials hidden.
2. The public HTTPS demo URL and model readiness.
3. A real sentence request and resulting Avatar motion.
4. The extension configured with the cloud origin; do not reveal its token.
5. A short English YouTube segment with visible captions, processing path and synchronized playback, including pause and seek.
6. The explicit ASL limitations.

Only the organizer can decide whether a late submission is allowed. The local recording cannot be described as a Vultr-running demo.
